Clash 无法访问 x.com / zaobao.com 根因诊断

现象：Clash Verge Rev 能开 google，但 x.com、zaobao.com 打不开。

排查路径（静态配置 + mihomo 运行时日志双向印证）：

  • 配置目录：C:\Users\Administrator\AppData\Roaming\io.github.clash-verge-rev.clash-verge-rev
  • 运行时合并配置：clash-verge.yaml（订阅 profiles/RTAb3ieJCxdl.yaml + 扩展 profiles/robVAXldOzsf.yaml）
  • 扩展配置 robVAXldOzsf.yaml：用户自建 prepend DIRECT 规则（tdx.com.cn / eastmoney / sina 等 A股数据源）
  • 外部控制器走命名管道（external-controller-pipe），TCP 9097 未监听 → API 只能读日志
  • 规则链尾部：GEOIP,CN,DIRECT → MATCH,⚓️其他流量
  • 代理组：🔰国外流量（select，默认日本—E3）/ ⚓️其他流量（select，首项=🔰国外流量，次项=🚀直接连接）

铁证（mihomo sidecar_latest.log 实际匹配）：

x.com:443          match Match                using ⚓️其他流量[DIRECT]   ← 关键
twitter.com:443    match DomainKeyword(twitter) using 🔰国外流量[日本—E3]
www.google.com:443 match DomainKeyword(google)  using 🔰国外流量[日本—E3]
www.zaobao.com:443 match DomainSuffix(zaobao.com) using 🔰国外流量[日本—E3]
www.zaobao.com.sg:443 match Match              using ⚓️其他流量[DIRECT]

根因：⚓️其他流量 组的当前选中项 = 🚀直接连接（不是默认首项 🔰国外流量）。于是所有「未命中订阅规则」的域名一律直连：

  1. x.com：订阅规则只有 DomainKeyword(twitter) 和 x.company，没有 x.com（规则集停留在 twitter.com 时代）→ 落 MATCH → ⚓️其他流量 → 直连 → 被墙。
  2. zaobao.com：走代理（JP 节点）→ 站点按境外 IP 302 跳到 zaobao.com.sg → .com.sg 无规则 → 落 MATCH → 直连 → 又 302 跳回 .com → 死循环。
  3. google 因为命中 DomainKeyword(google) 走代理，所以正常 —— 与「Clash 是否可用」无关，纯粹是分流差异。

实测数据（127.0.0.1:7897 混合端口，直连 vs 代理）：

目标直连走代理
google.com超时（被墙）200 ✓
x.comSSL 握手超时读超时 ✗
zaobao.com200302 循环
zaobao.com.sg302→.com302→.com

修法：

  • 首选（一键）：Clash Verge → 代理 → ⚓️其他流量 改选 🔰国外流量。所有未命中域名随即走代理，x.com 与 zaobao 一并解决。
  • 加固（防组选择被重置/订阅更新）：在 profiles/robVAXldOzsf.yaml 的 prepend 追加

DOMAIN-SUFFIX,x.com,🔰国外流量 与 DOMAIN-SUFFIX,zaobao.com.sg,🔰国外流量。

教训：⚓️其他流量 是全局兜底开关。「兜底=直连」型配置对任何未收录域名（新域名、改版域名、新兴站点）都会漏直连。用户自建的 prepend 直连规则本意正是防这个组漂移（见 09-11 注释），但当组被切成 DIRECT 时，方向反了 —— 该加的是「漏网域名→代理」规则，或把兜底组固定回代理。

Clash 修复执行：先测试 → 再写入（已落地并验证）

用户要求：先测试，再写入配置。

测试方法（关键技巧：mihomo 命名管道 API）：

  • 内核由 Clash Verge 启动，命令行带 -ext-ctl-pipe \\.\pipe\verge-mihomo-sidecar-release-<hash>，无 TCP 控制口（external-controller: ''）；secret = set-your-secret。
  • 用 PowerShell NamedPipeClientStream 手写 HTTP/1.1 请求即可调用完整 REST API（GET/PUT）。
  • 坑1：命令行出现 %XX 会被安全策略误判成 CMD 变量而拦截 → URL 编码/组名 emoji 要在脚本内部用 [Uri]::EscapeDataString + [char]::ConvertFromUtf32 构造，命令行只用 ASCII。
  • 坑2：默认 ExecutionPolicy 禁脚本 → 同一命令内先 Set-ExecutionPolicy -Scope Process Bypass -Force 再 & script.ps1。
  • 用到的端点：GET /version、GET /proxies/<urlencoded组名>、PUT /proxies/<组名> body {"name":"..."}、PUT /configs?force=true body {"path":"<abs clash-verge.yaml>","force":true} 热重载。

  1. 基线：x.com 经 7897 = 000(超时)；google = 200。
  2. 注入测试：API 把 ⚓️其他流量 切 🔰国外流量 → x.com=200、zaobao.com.sg=200、google=200、baidu 仍直连0.06s、出口IP=212.87.194.5 → 证明「导入国外节点」即有效修复。

  • x.com（订阅只有 twitter 关键字）

- DOMAIN-SUFFIX,x.com,🔰国外流量
- DOMAIN-SUFFIX,zaobao.com.sg,🔰国外流量

工程化沉淀：把管道 API 写成可复用脚本 ~/.workbuddy/skills/clash-verge-troubleshooting/scripts/clash_ctl.ps1
（自动从 verge-mihomo.exe 命令行提取 -ext-ctl-pipe 管道名、自动读 secret、字节级 de-chunk；动作 status/groups/to-foreign/to-direct/reload/raw）。技能升级 v1.1，新增 4 个坑：
① GET /proxies 是 chunked 响应，不 de-chunk 会报 无效的 JSON 基元: 683a（chunk 长度行混进来了）；
② 该接口外层是 {"proxies":{...}}，少取一层会得到空结果；
③ .ps1 必须纯 ASCII（PS 5.1 按 GBK 读无 BOM 的 UTF-8，中文注释会被误解析）；
④ 本会话 PowerShell 工具偶发不回显 stdout（只回 exit code 0，命令其实已执行）→ 输出重定向到文件再 Read。
