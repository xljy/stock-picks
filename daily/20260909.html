MCP 工具不可达 — 故障诊断（15:07）

现象：tdx MCP 工具全部不可达。ToolSearch 精确匹配 mcp__tdx-connector__tdx_screener / mcp__tdx-finance__tdx_screener 均失败，关键词搜索返回空。deferred 工具列表里 mcp__tdx-connector、mcp__tdx-finance 仅为空分组名（无具体工具），而 agent-mail/sheetagent 分组正常列出工具。

根因（已确认）：通达信 MCP 服务端启用 OAuth 认证，本地两条配置的 token 均无效。

证据链：

  1. 端点连通性：DNS 解析→TCP 连接→SSL 握手全部成功，返回 HTTP 401（应用层，非网络故障）
  2. 服务端响应：{"error":"unauthorized","error_description":"Missing Bearer authorization"} + resource_metadata: https://txmcp.tdx.com.cn:3001/.well-known/oauth-protected-resource
  3. OAuth 元数据：{"authorization_servers":["https://auth.tdx.com.cn"],"bearer_methods_supported":["header"]}
  4. 带假 Bearer 测试仍返回 Unauthorized access → 需有效 token，非格式问题
  5. daemon.log 记录 6 次：[McpApps] discovery failed for custom-mcp:tdx-finance: Unauthorized（2026-09-09 15:01~15:10 北京时间）

两条配置各自的问题：

  • ~/.workbuddy/mcp.json 的 tdx-finance：从未配置 Authorization 头（仅 url/type/timeout）→ 必然 401，是日志中报错的那条
  • connector:tdx-connector（账号目录 ae613ab4-8c26-485b-8d13-a5bc03e4c626/mcp.json）：有 AES-256-GCM 加密的 Authorization（存于 connector-states.json headerOverrides），但同文件标记 headerOverridesBearerStripped: true、staleManagedAuthHeadersPurged: true（9/5 23:57 迁移）→ 疑 Bearer 前缀被剥离或 token 过期

排除项：

  • 非网络/代理问题（三层握手全通）
  • 非 WorkBuddy 整体故障（agent-mail、sheetagent 工具正常）
  • 非配置丢失（bound=true, enabled=true）

时间线：9/3、9/4 tdx 仍可用 → 9/5 23:57 connector-states.json 做 auth header 迁移 → 9/9 失效

修复方向：

  1. 连接器管理页将「通达信 tdx-connector」断开重连，重新走 OAuth 拿新 token（首选）
  2. ~/.workbuddy/mcp.json 的 tdx-finance 无认证头会持续刷 Unauthorized 日志，应删除或补有效 token

备用数据源实测：

  • 腾讯财经 https://qt.gtimg.cn/q=sh000001 可用（返回上证指数 3951.51，gbk 编码）

  • 失败项始终是 custom-mcp:tdx-finance，从未是 connector:tdx-connector
  • 起始 2026-09-05 23:57，此后 9/5~9/9 每天持续，错误固定 Unauthorized
  • 失败时刻精确对应自动化运行点：09:10 / 10:35 / 14:43 / 15:45 / 17:00

结论：体感的"下午错误"不是时段规律，而是每次自动化启动都触发 MCP 发现、tdx-finance 必失败刷错误。真正的工具提供者 connector:tdx-connector 全程零报错。

tdx-finance 必失败原因：~/.workbuddy/mcp.json 该条目只有 url/type/timeout，无任何 Authorization 头；服务端 9/5 起启用 OAuth（auth.tdx.com.cn）→ 100% 401。它与 connector 指向同一 URL，属重复且失效的配置。

已执行修正：

  1. 备份 ~/.workbuddy/mcp.json → mcp.json.bak-20260909
  2. tdx-finance 加 "disabled": true（停止发现、停止刷错；配置保留可回滚）
  3. 给依赖 tdx 的自动化显式绑定 connectorIds=["tdx-connector"]：15:45 收盘反查、14:43 套利、17:00 全流水线（幂等，prompt 完整保留）

待办：9:26 竞价扫描、9:45 早盘、10:35 预判未显式绑定（可能已绑；view 接口不返回 connectorIds 字段，无法确认）。

生效条件：mcp.json 变更需重启 WorkBuddy 才生效。

关键认知（可复用）：诊断 MCP 故障先分清"哪条配置在报错"——mcp__tdx-connector__* 与 mcp__tdx-finance__* 是两个不同入口、同一 URL；日志里的名字（custom-mcp: vs connector:）是唯一可靠区分依据。诊断脚本已留：D:\WorkBuddy\Claw_mcp_diag.py（解析 daemon 日志，输出北京时间+错误分布）。
